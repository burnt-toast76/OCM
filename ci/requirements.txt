# CI dependency lock for the Python packages in software/.
#
# WHY THIS EXISTS
#   The pyproject.toml files declare dependencies with unbounded `>=` (a
#   deliberate choice for libraries -- see docs/decisions). But CI installs
#   fresh from PyPI on every run, so an unbounded `>=` lets an upstream release
#   silently break a build that no commit here touched -- which is exactly what
#   mcp 2.0.0 did (removed mcp.server.fastmcp; pytest aborted at collection).
#
# WHAT IT DOES
#   Every third-party version CI resolves is pinned here. The workflows apply it
#   as a pip CONSTRAINTS file (`pip install -c ci/requirements.txt ...`), so the
#   editable `ocm-*` packages still install from the working tree while their
#   third-party dependencies resolve to exactly these versions. Upstream releases
#   no longer change what CI installs; they enter only when this file is updated.
#
# HOW IT IS UPDATED
#   - Dependabot (.github/dependabot.yml, pip / directory: /ci) opens one PR per
#     bump; CI runs against the change, so every upgrade is isolated and gated.
#   - To regenerate by hand (Python 3.12, matching CI):
#       python3.12 -m venv /tmp/lockgen && /tmp/lockgen/bin/pip install \
#         -e software/ocm-core -e software/ocm-resolve \
#         -e software/ocm-generator -e "software/ocm-api[test]"
#       /tmp/lockgen/bin/pip freeze --exclude-editable | sort -f > ci/requirements.txt
#     then re-add this header.
#
# NOTE: mcp is held at 1.x by the `mcp<2` bound in ocm-api/pyproject.toml until
#   the FastMCP -> MCPServer migration lands; dependabot.yml ignores its major.
